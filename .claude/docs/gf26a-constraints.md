# GF26a Shuttle Constraints & Facts

_Last grounded: June 2026 (web search + TinyTapeout docs)._

## Process / shuttle
- **GF26a** uses the **GF180MCU** PDK — confirmed in this repo: `.github/workflows/gds.yaml`
  uses `TinyTapeout/tt-gds-action@ttgf26a` with `pdk: gf180mcuD`, and `test/Makefile` references
  `gf180mcu_fd_sc_mcu7t5v0` cells.
- This is a **different PDK** from the prior IHP26a port (IHP SG13G2) — see [porting-notes.md](porting-notes.md).

## Top-module interface (identical across all TT projects)
34 pins, fixed:
- `ui_in[7:0]` — dedicated inputs
- `uo_out[7:0]` — dedicated outputs
- `uio_in[7:0]` / `uio_out[7:0]` / `uio_oe[7:0]` — bidirectional (oe: 1=output, 0=input)
- `ena` (high when this design is selected), `clk`, `rst_n` (active-low)
- `top_module` must start with `tt_um_`.

## Clock (verified against tinytapeout.com/specs/clock/)
- Generated by the on-board **RP2040** (MicroPython "Commander") via PWM/PIO dividing its system clock.
- Configurable **1 Hz – 66.5 MHz**; practical max ~66 MHz, limited by the I/O pad
  (`sky130_ef_io_gpiov2_pad`) with up to ~10 ns pad→logic insertion delay — budget for it in timing.
- The IHP/VHDL design targeted **50 MHz** → ~97.5 kHz switching. On GF26a it can run faster;
  switching frequency scales proportionally with `clk`. Set `clock_hz` in `info.yaml` and
  `CLOCK_PERIOD` in `src/config.json` accordingly **(but do not otherwise edit config.json)**.

## Demoboard (what ships)
Carrier board on the TT demoboard: 8 DIP switches → `ui_in`; 7-seg display + dot ← `uo_out`;
RP2040 selects the active project, drives `clk`, can provide SPI RAM; PMOD headers break out `uio`;
USB-C for power + browser terminal.
