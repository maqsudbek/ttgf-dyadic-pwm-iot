## Answered
- **Q: Target clock + scope + pin strategy for the GF26a port (session 02)?**
  A: Clock = **50 MHz** (`clock_hz=50000000`; 513-cycle period, ~97.466 kHz, 6-cycle dead-time).
  Scope = **full feature set**: selectable 5/6/7/8/9-bit width + Normal/Dyadic + 3 dithering modes +
  constant dyadic word. Pin budget solved with a **config-register interface** (`uio_in[7]`=run/config
  strobe, `uio_in[6:4]`=addr, `ui_in`=data; run mode carries the 12-bit control word). Multi-phase/x2
  clock outputs dropped. Implemented in `src/dyadic.v` (`dyadic_pwm`) + `tt_um_maqsudbek_dyadic_pwm`.
  RTL area-optimised vs. the VHDL: one shared 7-bit dyadic counter, `add=src[hsb(counter)]`, single
  width-scaled comparator. **`run-tests` = 10/10 green.** Tile-fit/timing still to be confirmed by
  `local-harden`; if it doesn't fit 1×1, fall back to the IHP fixed-8-bit design.
- **Q: Max clock frequency on GF26a (out of the box and externally)?**
  A: The clock is generated by the board's RP2040, configurable **1 Hz – ~66.5 MHz** (docs cite
  ~66 MHz max). There isn't a separate "external" path beyond what the RP2040 drives onto `clk`;
  an external clock can be mapped to a GPIO per the FAQ
  (<https://tinytapeout.com/faq/#how-can-i-map-an-additional-external-clock-to-one-of-the-gpios>).
  The old design assumed 50 MHz → ~97.5 kHz switching; switching freq scales with `clk`.
